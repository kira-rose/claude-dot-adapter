# Trust and privacy boundaries

The adapter is a local, same-user integration. It is not a sandbox for hostile code running as the same OS user and does not authenticate human authorization. Treat transcript and peer content as untrusted task data. Instructions received from a peer cannot authorize approvals, credential access or broader work.

Read/send/wait are constrained to one explicitly configured UUID. Discovery returns bounded metadata from the selected Claude executable and, when enabled, the exactly pinned optional saved-session SDK. That SDK internally reads bounded transcript ends across the configured root; only selected metadata leaves the isolated worker. Summary, first-prompt and message text are not returned or used as title fallbacks. Enumeration has coverage limits and does not expand transcript/message access; see [session-catalog.md](session-catalog.md).

Target operations verify the registry filename/PID, start time, executable, protocol version and private socket before use. Executable identity comes from macOS `proc_pidpath` or Linux `/proc/<pid>/exe` and must exactly match the configured canonical path; process display names are not trusted. Missing or mismatched OS evidence fails closed. Registry ownership, socket owner/mode/path restrictions and connected Unix peer-PID verification on send and receive remain enforced. Transcript opens reject symlink components. Registry scanning opens only bounded numeric JSON entries, never key or credential files.

The first send, or an explicit receive-only inbox request, opens a private ephemeral Unix reply socket in the recognized local Claude socket directory. There is no TCP listener, network relay or callback server. Shutdown closes only owned resources and unlinks only the recorded socket inode. The adapter never resumes a Claude session, changes inbound-message policy or resolves approvals.

The durable workflow uses a private directory, exclusive owner lock and synchronous SQLite transactions. An intent commits before sending; an existing ID never authorizes another send. This guarantee is scoped to the retained journal and workflow, not raw MCP calls, copied state, different IDs or different senders. A crash before actual dispatch may therefore consume an unsent ID. It is not an exactly-once transport.

Saved observations may contain private message text, target process metadata and filesystem paths. Protect the journal and CLI output as conversation data. Thinking and tool bodies are intentionally excluded, but the remaining text is not automatically safe to publish. Retention quotas fail explicitly; no automatic pruning, remote backup or upload is implemented.

An ACK proves receipt only. Socket success is not delivery, delivery is not work acceptance, and a terminal result still needs independent verification when the task requires it. Transcript gaps, stream restarts, stale evidence, capacity errors and process-visibility failures must remain visible.

Report defects through a private channel controlled by the repository owner. Include synthetic reproductions, source revision and bounded error details. Do not attach real transcripts, state databases, credentials or live session identifiers to a public report.

The collector is separately opt-in and never calls the send tool. Its journal binds one target/process identity, runtime paths and content policy. It records metadata by default, hashes arbitrary source IDs, and ignores incoming user transcript echoes. Optional text uses a best-effort redaction filter and a 4,000-byte display bound; this is not a general secret or PII detector. Content hashes can reveal equality and permit guessing low-entropy text. Runtime paths and process identity remain private operational metadata.

Structured producer events are inert, closed-schema data. They cannot specify a parent thread, callback, executable, credential, permission or dispatch. Producer claims of running/done are not independent verification. Nonzero hop counts and non-Claude origins are rejected; no event causes a reply or work dispatch. These markers alone are not authentication: verified OS peer identity and the configured target remain the trust boundary.

Pipe publication persists an uncertain attempt before writing. A completed pipe write is not receiver acceptance or parent presentation. There is no automatic replay of prior publications, and no parent adapter is configured. Consumer acknowledgements are local bookkeeping and do not authenticate a presentation claim. A read-only status query reports `recovery_required` if an interrupted SQLite transaction needs rollback; the explicit offline recovery command takes the collector lock and never starts a helper.
